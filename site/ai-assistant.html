So how do you actually use these tools?

Until recently the honest answer was: read the README, then prepare the inputs by hand. A Markdown transition table for the state machine. An old header and a new header for interface sync. A JSON rule file for the injector. Then run the right script, in the right order, with the right paths. None of that is necessary any more. Describe what you want in plain English and the AI writes those inputs and drives the tools for you. What you do is type one sentence.

By hand, and in plain English

before — you prepare everything
# author state_machine.md yourself, then run three stages
python3 table_to_json.py state_machine.md
python3 json_to_cpp.py ./out/state_machine.json
python3 json_to_mermaid.py ./out/state_machine.json

# write the new interface header yourself, then diff it
python3 interface_sync.py \
    --old test/include/IObserver_old.h \
    --new test/include/IObserver.h \
    --src test/src

# hand-write config.json: rules, directories, excludes
python aspect_injector.py --config config.json
After — you say what you want
An order system that starts in Pending, moves to Paid on PaymentReceived, then to Completed on OrderDelivered.
Update IObserver_old.h: remove OnConnected, add OnError(int err_code). Sync every derived class under test/src.
Add trace and validate logging to every function under test/src/hot, but skip AlphaEngine.cpp.

The router reads the intent, picks one of the three tools, generates the spec or config that tool expects, runs the pipeline, and hands back the generated files and a diff.

What that actually buys you

One entrance, not four

No need to know which script does what, that three of them run in sequence, or which flags each one takes. The request picks the tool, not you.

No input format to learn

The Markdown spec and the JSON config are still produced — you can read them, keep them, edit them by hand. You just no longer have to author them to get started.

The model never edits your code

It only turns English into a specification. Every actual edit is still made by the deterministic pipeline — libclang for the AST, Jinja2 for the code. Intent from the model, correctness from the tools.

Visible and reversible

Every generated file is listed and every edit is shown as a unified diff, so you review the change instead of trusting it. One button puts the tree back the way it was.

Out of scope stays out of scope

Ask it about the weather and it says so, and touches nothing. A request is never forced onto a tool that was not built for it.

Nothing to install

No Python, no libclang build, no LIBCLANG_PATH, no template directory. It all runs in a container — you only need a browser.
